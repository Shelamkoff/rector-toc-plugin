## Remaining evidence gaps

These are explicitly **not** claimed as completed checks:

1. Firefox/WebKit native editing and accessibility, keyboard navigation with a screen reader, and enforcing Trusted Types CSP across the TOC-specific browser scenarios.
2. Performance and GC pressure for unusually large documents, including rebuilding thousands of TOC links on every heading edit.
3. Installation and execution of a packed tarball in a clean downstream application; `npm pack --dry-run` is a packaging inventory, not consumer acceptance.
4. The pure `htmlToText()` helper currently decodes a restricted named-entity subset (plus numeric references), not the full HTML5 named-character-reference table. Documents using other named entities could show the literal entity in TOC labels. A complete decoder should be evaluated against runtime size and Trusted Types constraints rather than extending the handwritten table ad hoc.
5. Public npm publication has not been performed.

## Review conclusion

Within the tested Node/Chromium and public Rector v2 contract scope, the three reproduced defects have been fixed and the existing feature/browser checks remain green. This does not imply publication or cross-browser release acceptance.
